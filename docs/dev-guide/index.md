# 媒体云工作台（studio）交互设计说明

工作台界面只回答一个问题：**每个动作归哪一栏**。本文记录定稿的设计逻辑，新增界面前先读它。

## 三栏骨架

```
导航栏 → 草稿清单（列表面板）→ 详情区（工具带 + 编辑器 + 预览）
```

- **无顶栏**：没有横跨全窗的标题栏，应用名与操作都在侧边；详情区通高直达窗口底
- **等高**：草稿清单与导航栏等高通栏
- **设置沉底**：设置入口在导航栏底部、与内容分区（文章/图文/视频）拉开间距——设置不是内容分区

## 归属原则：动作作用于谁，就住哪一栏

| 栏 | 作用域 | 动作 |
|------|------|------|
| 导航栏 | 应用 | 分区切换、设置 |
| 草稿清单 | 集合（这一批草稿） | ＋存为新草稿、保存当前草稿、点项打开 |
| 详情工具带 | 详情（当前这篇） | 复制到公众号、推到公众号；未来的主题切换、字号、导出等编辑工具 |

判断一个新按钮放哪：问它动的是谁。动「当前这篇」的进工具带，动「整份草稿集合」的进清单，动「应用」的进导航栏。清单底部不放交付按钮——交付不是集合动作。

## 详情工具带的规矩

工具带是**工具带，不是标题栏**，守住两条：

1. **安静**：背景比详情区浅一档，按钮次要样式起步，不抢编辑器的视觉焦点
2. **主行动唯一**：只有「复制到公众号」是主按钮；配好服务端后才出现「推到公众号」（次要样式），没配连接就不给第二个按钮
3. **靠右**：按钮放工具带右端——写作流程从左侧编辑、经预览，交付是流程的终点，与成品（预览）同侧

## 预留分区

「图文」「视频」是占位分区：导航位置现在就定下，开发时直接往里填，不再动骨架。
